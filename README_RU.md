# Steam Cleanup Tool

[English documentation](README.md)

Утилита для Windows, которая сначала показывает план, а затем при явном
подтверждении очищает выбранные файлы Steam и найденные записи реестра. Проект
не связан с Valve Corporation или Steam.

> **Внимание:** реальный режим безвозвратно удаляет файлы и данные реестра.
> Публичная конфигурация всегда поставляется с `"dry_run": true`.

## Возможности

- поиск по именам разделов, именам параметров и данным параметров реестра;
- обход настроенных корневых разделов `HKCR`, `HKCU`, `HKLM`, `HKU`, `HKCC`;
- независимые запросы, режимы `exact`, `partial`, `regex` и исключения;
- компактное отображение бинарных данных без тысяч `\x00` и `\xfe`;
- сохранение папки `steamapps` и файла `steam.exe` при очистке клиента;
- резервные `.reg`-копии до любых удалений;
- остановка процессов Steam после подтверждения и запуск `steam.exe` в конце;
- защита системных папок, проверка сохраняемых файлов и опечаток конфигурации;
- работа из исходного Python-файла или готового EXE.

## Как пользоваться готовым релизом

1. Скачайте `SteamCleanupTool-Windows.zip` в разделе Releases и распакуйте его.
2. Откройте настройки через `edit_config.bat` и оставьте `"dry_run": true`.
3. При желании запустите `check_config.bat` для быстрой проверки настроек и путей.
4. Запустите `run_cleanup.bat` двойным щелчком и разрешите запуск от администратора.
5. Проверьте весь предпросмотр в консоли и последнюю секцию `cleanup_log.txt`.
6. Только если каждый путь верен, поменяйте `"dry_run"` на `false`.
7. Запустите утилиту повторно. После предпросмотра очистка начнётся
   автоматически по окончании 15-секундного обратного отсчёта.

В режиме предпросмотра процессы не останавливаются и ничего не изменяется.
Реальный порядок работы:

1. полный предпросмотр;
2. 15-секундный обратный отсчёт;
3. резервное копирование затронутых разделов реестра;
4. остановка процессов Steam;
5. удаление файлов;
6. удаление записей реестра;
7. запуск `steam.exe`.

Чтобы отменить операцию во время отсчёта, закройте окно или нажмите `Ctrl+C`.
Для возврата ручного подтверждения установите
`"confirmation": {"mode": "type_delete", "countdown_seconds": 15}`.

После удаления служебных файлов сохранённый `steam.exe` обычно восстановит или
заново загрузит клиент. `steamapps` сохраняется, но резервная копия важных игр и
данных всё равно рекомендуется.

## Настройка config.json

Настройки находятся во внешнем `config.json` рядом с EXE или скриптом. Поэтому
для изменения конфигурации не требуется пересобирать программу. Относительные
пути журнала и резервных копий считаются от папки этого JSON-файла.

Основные параметры:

- `dry_run` — `true` для предпросмотра, `false` для разрешения подтверждённого удаления;
- `confirmation.mode` — автоматический `countdown` или ручной `type_delete`;
- `confirmation.countdown_seconds` — задержка до автоматического продолжения;
- `registry.enabled` — включение работы с реестром;
- `registry.targets` — проверяемые корневые разделы и начальные пути;
- `registry.search_terms` — независимые запросы `dota`, `steam`, `valve`;
- `registry.exclude_terms` — ложные совпадения, например `msteams`;
- `registry.exclude_path_suffixes` — необязательные исключения веток по окончанию пути;
- `registry.match_type` — `exact`, `partial` или `regex`;
- `registry.delete_matching_keys` — удалять совпавший раздел целиком с поддеревом;
- `registry.delete_matching_values` — удалять совпавшие параметры;
- `registry.backup_before_delete` — требовать экспорт `.reg` перед удалением;
- `folder.path` — абсолютный путь установки Steam;
- `folder.keep_folder` и `folder.keep_file` — точные имена сохраняемых объектов;
- `steam_processes` — список процессов, ожидание, принудительная остановка и перезапуск.

Пустой `steam_processes.executable` означает `<folder.path>\steam.exe`. Можно
указать абсолютный путь или имя файла относительно `folder.path`. Неизвестные
ключи JSON считаются ошибкой: опечатанная защитная настройка не будет молча
проигнорирована.

### Процессы Steam

По умолчанию перед реальным удалением проверяются и останавливаются:

```json
[
  "steam.exe",
  "steamwebhelper.exe",
  "steamerrorreporter.exe",
  "steamerrorreporter64.exe",
  "gameoverlayui.exe",
  "gameoverlayui64.exe"
]
```

Сначала выполняется обычное завершение и ожидание, затем при необходимости —
принудительное. Если какой-либо процесс остановить не удалось, удаление не
начинается. После начавшейся реальной очистки запуск Steam выполняется даже при
ошибке одного из удалений.

### Реестр

Пустой `start_path` означает обход раздела от корня и требует
`allow_full_hive_scan: true`. Такой обход может занять много времени. Для
максимального доступа запускайте утилиту от администратора.

При `match_type: "partial"` совпадение ищется как подстрока без учёта регистра.
Если совпало имя раздела и включено `delete_matching_keys`, будет удалено всё
его поддерево. Поэтому первый запуск обязательно должен быть с `dry_run: true`.

Бинарные значения продолжают участвовать в поиске, но отображаются как
`<binary data: N bytes>`. Длинные текстовые значения сокращаются только в логе;
это не меняет поиск и план удаления.

## Запуск из исходников

Нужны Windows 10/11 и Python 3.9 или новее. Сторонние библиотеки для работы не
требуются.

```powershell
py -3 cleanup_tool.py --config config.json
```

Создание отсутствующего безопасного конфига:

```powershell
py -3 cleanup_tool.py --config config.json --create-config
```

Проверка настроек и путей без сканирования реестра:

```powershell
py -3 cleanup_tool.py --config config.json --check-config
```

## Сборка EXE

Запустите `build_exe.bat`. Он создаст отдельное окружение `.build-venv`, установит
PyInstaller и подготовит `SteamCleanupTool-Windows.zip`. Для сборки нужен
интернет, готовому EXE установленный Python не требуется.

Workflow в `.github/workflows/build-windows.yml` автоматически проверяет и
собирает Windows-архив. При создании тега вида `v1.1.0` архив прикрепляется к
GitHub Release.

Все файлы должны лежать непосредственно в корне репозитория. Путь workflow
должен быть ровно `.github/workflows/build-windows.yml`, а не
`outputs/.github/workflows/build-windows.yml`. Исходный ZIP необходимо
распаковать — загрузка самого ZIP как одного файла не активирует Actions. Если
Actions отключены, включите их в **Settings → Actions → General**.

## Коды завершения

- `0` — успех, предпросмотр или отмена пользователем;
- `1` — удаление или перезапуск завершились с ошибками;
- `2` — ошибка конфигурации или запуска;
- `3` — резервная копия реестра не создана, очистка отменена;
- `4` — процессы Steam не остановлены, очистка отменена.
